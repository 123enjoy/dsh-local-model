# 分布式系统构建平台运维指南（测试文档）

## 1. 背景
本平台用于每日 200+ 次微服务构建，分布在 3 个构建机群。近 7 天构建成功率 97.3%，平均构建时长 4 分 21 秒，p99 时长 9 分 05 秒。
DISTILLED_ARTICLE_MARKER_KQ17 是本次测试的唯一标记，请务必在摘要中保留它。

## 2. 架构概述
每个构建任务由调度器分发给 worker，worker 在沙箱容器内执行编译、测试、打包三步流水线。
构建产物上传到制品库，按 git commit hash 归档，保留 90 天。
失败任务自动重试 2 次，第二次重试启用全新缓存目录。

## 3. 已知问题与修复
最近发现 ssh2 原生模块编译失败（错误码 E5291），根因是构建机缺少 OpenSSL 开发头文件。
修复命令：choco install openssl，然后 pnpm rebuild ssh2。
当前有 3 个 worker 处于离线状态（w2、w5、w7），原因分别是磁盘满、证书过期、依赖锁冲突。
队列积压 1284 个任务，预计 40 分钟内消化完毕。

## 4. 安全规范
所有构建密钥存储在 Vault 中，worker 通过短期令牌访问，令牌有效期 15 分钟。
日志中的敏感字段（密码、token）在采集时即被脱敏，原始值不落盘。
生产环境的数据库连接串仅允许通过内网专线访问，公网不可达。

## 5. 性能调优建议
- 构建缓存命中率当前 61%，提高到 80% 可节省约 30% 构建时间。
- p99 偏高的主要原因是原生模块编译无缓存，建议将 node_modules 缓存策略改为按 lockfile hash 分片。
- 建议把调度器的队列上限从 500 提到 2000，以消纳突发提交。

## 6. 后续计划
下个迭代将引入构建矩阵并行化，预计把平均构建时长再压 30%。
同时计划把制品保留策略改为智能淘汰：热制品保留 180 天，冷制品 30 天。

## 7. 附录：值班联系方式
一线值班群：ops-oncall（飞书），响应目标 5 分钟内。
升级路径：ops-oncall -> oncall-l2 -> 平台负责人。

# 分布式系统构建平台运维指南（测试文档）

## 1. 背景
本平台用于每日 200+ 次微服务构建，分布在 3 个构建机群。近 7 天构建成功率 97.3%，平均构建时长 4 分 21 秒，p99 时长 9 分 05 秒。
REPEAT_MARKER_4 是本次测试的唯一标记，请务必在摘要中保留它。

## 2. 架构概述
每个构建任务由调度器分发给 worker，worker 在沙箱容器内执行编译、测试、打包三步流水线。
构建产物上传到制品库，按 git commit hash 归档，保留 90 天。
失败任务自动重试 2 次，第二次重试启用全新缓存目录。

## 3. 已知问题与修复
最近发现 ssh2 原生模块编译失败（错误码 E5291），根因是构建机缺少 OpenSSL 开发头文件。
修复命令：choco install openssl，然后 pnpm rebuild ssh2。
当前有 3 个 worker 处于离线状态（w2、w5、w7），原因分别是磁盘满、证书过期、依赖锁冲突。
队列积压 1284 个任务，预计 40 分钟内消化完毕。

## 4. 安全规范
所有构建密钥存储在 Vault 中，worker 通过短期令牌访问，令牌有效期 15 分钟。
日志中的敏感字段（密码、token）在采集时即被脱敏，原始值不落盘。
生产环境的数据库连接串仅允许通过内网专线访问，公网不可达。

## 5. 性能调优建议
- 构建缓存命中率当前 61%，提高到 80% 可节省约 30% 构建时间。
- p99 偏高的主要原因是原生模块编译无缓存，建议将 node_modules 缓存策略改为按 lockfile hash 分片。
- 建议把调度器的队列上限从 500 提到 2000，以消纳突发提交。

## 6. 后续计划
下个迭代将引入构建矩阵并行化，预计把平均构建时长再压 30%。
同时计划把制品保留策略改为智能淘汰：热制品保留 180 天，冷制品 30 天。

## 7. 附录：值班联系方式
一线值班群：ops-oncall（飞书），响应目标 5 分钟内。
升级路径：ops-oncall -> oncall-l2 -> 平台负责人。
